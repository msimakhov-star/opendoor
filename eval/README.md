# opendoor_eval

1. Use `cd` to navigate into this directory, then run: `uv run run_eval.py --results "<core>/data/runs/<run_id>/results.json"` (this supports either an unadorned list of PracticeResult dictionaries or a container object storing the list under `results` or `practices`).
2. The script displays the summary and writes `EVAL.md` (supply `--out other.md` to store findings across separate runs). Running `uv run selfcheck.py` validates the evaluation logic offline: two introduced faults must return as exactly two discrepancies.
3. Evaluation is restricted solely to the 20 Newham pages inside `texts/`; additional practices within the dataset are set aside, and tagged pages that the process was prevented from reaching are marked as failures (`not_checked`).

A candid limitation: the target classifications were established using LLMs (relying on three blind LLM assessors, with code calculating the consensus outcome). No person has checked them yet. Under no circumstances describe them as human-labelled. While all 20 pages showed complete agreement, three comparable models might share identical flaws, and 5 pages received merely a medium-confidence rating. An operator can resolve any tag manually in `overrides.json`, such as `{"F84014": "unclear"}`. The direct-quote comparison inspects against the web copy previously saved in `texts/`, meaning that any page revised afterwards might produce a false negative. Because this involves only 20 pages from one local authority, state the specific numbers rather than asserting overall accuracy. The software analyses published website text, not reception desk behaviour.
